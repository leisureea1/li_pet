# 项目代码审查报告

审查日期：2026-07-31  
审查范围：项目入口、核心模块、技能系统、Web 设置页、更新机制、打包配置与现有测试。

## 主要问题

### 1. 严重：仓库硬编码 API Key

- `core/config.py:84` 内置了 DeepSeek API Key，并会在用户未配置时自动持久化。
- `skills/weather.py:25` 内置了天气服务 API Key。

这些凭据会随源码和安装包公开，可能造成额度盗用及费用损失。应立即吊销现有 Key，并改为用户配置、环境变量或 CI Secret。

### 2. 严重：历史页面存在存储型 XSS

- `core/web_server.py:590` 将聊天内容未经转义直接拼接进 `innerHTML`。
- `core/web_server.py:622` 的设置接口会返回包括 API Key 在内的完整配置。

恶意用户输入或模型输出可在打开历史页面时执行脚本，并通过同源接口读取 API Key。历史内容应通过 `textContent` 或安全 DOM API 渲染，设置接口不应回传完整密钥。

### 3. 高：CI 构建当前无法在全新检出中运行

- `.github/workflows/build.yml:47` 执行 `pyinstaller pet.spec --clean`。
- `.gitignore:8` 排除了所有 `*.spec` 文件，当前 `pet.spec` 不存在于 Git HEAD。
- 本地 `pet.spec` 引用了 BGE 模型，但工作流只下载 Whisper 模型。
- macOS 工作流在 `.github/workflows/build.yml:63` 期待 `dist/pet.app`，而当前 spec 没有 `BUNDLE` 配置。

应将有效的 spec 文件纳入版本控制，补齐模型下载步骤，并为 macOS 添加正确的应用包构建配置。

### 4. 高：首次聊天可能永久停在“思考中”

- `core/router.py:91` 下载语义模型时没有设置超时。
- `core/router.py:62` 的模型下载发生在初始化异常处理之外。
- `core/chat.py:180` 调用路由器时，聊天线程的主异常处理尚未开始。

当模型缺失且下载失败或网络无响应时，异常可能直接终止聊天线程，界面也收不到失败回复。应为下载设置超时、使用临时文件原子替换，并将整个路由过程纳入聊天线程异常处理。

### 5. 高：忙碌期间发送的键盘消息会丢失

`core/chat.py:292` 在聊天线程运行时只把新消息写入 `_pending_message`，但项目中没有完成回调消费该字段。上一轮请求未结束时发送的新键盘消息会永久丢失。

应实现明确的 FIFO 消息队列，并在 `QThread.finished` 后启动下一条消息；或者在 UI 层禁用输入并明确提示用户。

### 6. 中：音乐侦测容易误报且状态不会清空

`pet.py:936` 将包含 `" - "` 的活动窗口标题推断为音乐。浏览器页面、文档和其他应用标题都可能满足这个条件。切换到不含分隔符的窗口后，代码也不会调用 `update_music("")`，导致旧歌曲状态长期残留。

应恢复基于系统媒体会话的检测，并始终更新空播放状态。窗口标题只能作为经过播放器进程白名单约束的回退方案。

### 7. 中：自动更新缺少完整性验证

- `core/updater.py:61` 直接下载发布资产。
- `pet.py:461` 下载完成后直接执行安装包。

当前仅依赖 HTTPS，没有校验 SHA-256、代码签名或发布者身份。应随 Release 发布校验文件，并在执行前验证哈希及平台签名。

### 8. 中：TTS 重叠时可能冻结界面并产生播放竞争

- `pet.py:649` 在 GUI 线程调用 `quit()` 后同步等待最多三秒。
- `core/chat.py:21` 的 TTS 工作函数没有运行 Qt 事件循环，因此 `quit()` 无法中断正在执行的网络请求。

旧线程仍可能在稍后发出完成信号，与新语音争用播放器和临时文件。应使用可取消的任务设计，避免在 GUI 线程调用 `wait()`。

### 9. 中：隐私说明与实际存储不符

- `core/utils.py:22` 使用固定密钥 XOR 和 Base64 保存配置，这不属于安全加密。
- `core/memory.py:16` 将聊天历史和长期记忆直接存入明文 SQLite。
- `README.md:36` 声称 API 密钥、配置和聊天历史均已加密。

应使用系统凭据存储保存 API Key；如确需加密本地数据库，应使用成熟的认证加密方案并妥善管理密钥。同时应修正文档，避免给用户错误的安全预期。

2. 修复聊天路由异常边界和消息队列，避免卡死与消息丢失。
3. 将可复现的 PyInstaller 配置纳入 Git，并修复 Windows/macOS 构建流水线。
4. 为更新包增加完整性验证，修复 TTS 生命周期和音乐状态管理。
5. 补充核心单元测试、线程行为测试和 CI 静态检查。
